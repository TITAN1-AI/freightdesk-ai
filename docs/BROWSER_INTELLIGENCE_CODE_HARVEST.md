# Browser Intelligence code harvest — WebBridge V2

Research/design completed 2026-09-12. **Build a FreightDesk-native intelligence pipeline behind X1. Borrow document indexing, browser semantics, selector search and mutation bookkeeping; retain FreightDesk's business identity, action authority and evidence acceptance.** No inspected framework is an appropriate replacement for X1, and none solves the complete causal workspace-identity problem.

This review examined actual source in 11 repositories at pinned revisions, plus one version/hash-pinned Healenium dependency. No third-party implementation was incorporated, dependency installed, project demo executed, or production code changed. No Ascend/browser execution, extension reload, lease, selector change or operational runtime inspection was part of this research. The completed X1 causal-debugging track remains separate.

## Keep, refactor, replace and retire

This comparison uses actual [webbridge.js](../extensions/ascend-x1/webbridge.js), [workspace.js](../extensions/ascend-x1/workspace.js), [reader.js](../extensions/ascend-x1/reader.js), [mapping_store.py](../executors/ascend_extension/mapping_store.py), [context assembler](../integrations/ascend/context_assembler.py) and [provider-map bundle](../integrations/ascend/provider_map_bundle.py). Names alone do not imply the current implementation already supplies a general graph or adaptive solver.

| Current component | Primary disposition | What stays / what replaces it |
| --- | --- | --- |
| BrowserSensor | KEEP | Keep the small X1-only facade and authenticated execution boundary. Refactor its output to MetadataProjector + observation bindings; no external runner. |
| DOMSnapshot | REPLACE | Replace the small container Map as canonical representation with immutable DocumentGraph + NodeLedger + coverage. Retain bounded scope and trace measurements. |
| DOMDiff | REPLACE | Replace reference-only matching with MutationJournal + StateDiff. Preserve useful existing direct/new/visible/selected evidence and no-op behavior. |
| LocatorGraph | MERGE | Move typed relations into one shared RelationshipGraph; controls and schemas are views over those nodes. LocatorSignature/alternatives belong in LocatorEngine. Avoid duplicate competing graphs. |
| AdaptiveLocator | REPLACE | Exact tuple matching becomes the fast first stage of bounded candidate retrieval/ranking. Keep proposal-only acceptance, exact workspace gates and ambiguity stops. |
| ProviderContract | REFACTOR | Move generic canonical hashing to a utility; retain a real adapter interface for identity, vocabulary, view semantics, approved navigation and independently validated field meanings. Append-only versions remain. |
| EvidenceScorer | REFACTOR | Replace one ordinal result with claim-specific evidence, contradictions, feature contributions and candidate margin. Retain hard proof levels and separate policy authorization. |

Delete superseded duplicate traversal/scoring helpers **only after** offline behavioral parity and the replacement's gated migration. Nothing is deleted in this task. Keep the observed Ascend board acceptance, native/worker/router guards, DPAPI/HMAC enrollment, read leases, pause/revoke, presence, exact identity and write blocks. Keep `VerifiedAscendLoadContextAssembler`: candidate maps do not bypass its separate read-mapping validation and fresh provider-observation requirements.

There is one concrete privacy distinction to close in future implementation: legacy `webbridge.js:graph` reads a field's `.value` or text to compute `value_present`; the currently validated `workspace.js` metadata path does not. “Values not exported” and “values never read” are different claims. V2 must test the latter with throwing value getters, not merely scan output for private strings. This research does not assert that the successful exact workspace capture leaked data or modify either path.

Crawl4AI's examined license appends a prominent attribution requirement to Apache text; it must not be logged as ordinary Apache clearance. [The provenance plan](WEBBRIDGE_V2_PROVENANCE.md) gives per-source classifications and future notice handling, without pretending research is legal clearance.

## What FreightDesk should own

Generic node indexing, label/role semantics, selector enumeration, tree signatures, mutation ordering and table slot arithmetic are established engineering. Rebuilding every algorithm without studying these implementations would waste effort.

FreightDesk-specific value is the acceptance layer: exact business workspace identity, ownership across SPA changes, provider-backed section/field evidence, read/write classification under ActionPolicy, observed-versus-validated contract maturity, authorization-bound recovery, provenance and reconciliation into shipment context. No inspected library makes these facts true merely by returning a selector or a confidence score.

The recommended design is **one immutable DocumentGraph, Control/Schema views, a LocatorEngine, MutationJournal/StateDiff, ApplicationStateGraph, EvidenceEngine and RecoveryPlanner**, all behind X1 and interpreted by AscendProviderContract. An atomic observation record joins map and evidence before the existing assembler can consider it. The [roadmap](WEBBRIDGE_V2_ROADMAP.md) estimates a **20–35% net reduction in custom browser-intelligence engineering**, explicitly a planning judgment to calibrate with early phases, not a measured result or a reduction in all FreightDesk development.

The largest remaining risk is proving ownership and read-only meaning when an SPA exposes incomplete semantics and unrelated updates coincide with navigation. Better snapshots improve the evidence; they cannot manufacture that proof. Stop on ambiguity, preserve unknowns, and evaluate further observations only under separately authorized validation. No implementation or new live attempt starts from this research handoff.
