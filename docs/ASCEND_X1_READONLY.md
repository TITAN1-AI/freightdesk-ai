different memberships, invalid target dates, an All Loads view or changed hash fail closed.

## Host and executor boundary

The existing exact extension pin, Windows/runtime binding, DPAPI key, one-use pairing, HMAC direction
and sequence protection remain. Outgoing HMAC messages are serialized with the heartbeat. There are
no new extension permissions: `nativeMessaging` and the existing exact Ascend host permission only.
The page cannot issue commands to the worker or expand the fixed operation list.

PAIRED transport/global `read_dispatch_enabled=false` and the old generic adapter production switch
remain separate from signed **READ_DISPATCH**. Only the new host controller issues this short command
grant after checking the local owner release, ActionPolicy ALLOW, tenant pause/takeover controls,
sequence, selected tab/document, request replay and board/load scope. It checks those gates again on
receipt. Operational READ_LOAD/READ_STOPS/READ_ASSIGNMENT and all mutation/JS/selector/URL commands remain
unavailable. The identity opener must be a non-submit control with a same-document fragment or no href;
arbitrary navigation, form actions, downloads and new-window targets are rejected.

No DOM read happens on content-script load, tab listing, selection, pairing or authorization-plan load.
Only a verified native grant activates a read in the selected isolated-world content script.
Tab close, reload, non-fragment navigation or a disconnected pairing/content port invalidates it.
Hash-fragment changes from a same-page opener are allowed; path/query/document changes are not.
Native pairing loss cancels the outstanding content port; leases are checked around asynchronous work
and immediately before the single opener click. No late response may establish identity after loss.

Append-only `x1_read_grants` and `x1_read_events` are stored only in
`C:\FreightDeskRuntime\Data\booking-logistics\ascend-native\bridge.sqlite3` on owner execution. Events
contain safe dispatch checkpoints/receipts or allowlisted error codes; no raw DOM/private fields.
The first dispatch durably consumes the entire four-step test; a crash cannot resume it in another
native session. Lost connections may leave DISPATCHED/UNKNOWN without a completed receipt. Treat that
as consumed uncertainty, never as success. Pairing/audit history and previous attempt ledgers are preserved.
