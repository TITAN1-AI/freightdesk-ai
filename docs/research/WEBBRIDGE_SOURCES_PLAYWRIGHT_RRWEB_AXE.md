## PW1 — accessible relationships and explicit visibility dimensions

[roleUtils.ts](https://github.com/microsoft/playwright/blob/d1ead3ecca23182f2d06d761c28e3d4edafb6595/packages/injected/src/roleUtils.ts#L516-L803): `computeAccessibleNameComposite`, `getElementAccessibleName`, `getTextAlternativeInternal`, `getAriaRole`. The name result includes contributing elements and a derived-from-content flag, not just a string. Ordered IDREF traversal, visited-element sets, native labels, implicit/explicit roles and invocation-scoped caches preserve the reason a name exists. Hidden referenced labels are treated differently from hidden ordinary content. This is a substantially stronger semantic primitive than FreightDesk's visible label/ARIA/previous-sibling lookup.

Dependencies: DOM APIs, internal CSS/text/ARIA utilities and spec tables. It is not a small standalone drop-in. Embedded controls can contribute their current values to an accessible name. **ADAPT / SAFE_TO_ADAPT_WITH_NOTICE**, subject to file/dependency notice review, for relation resolution and role tables. A metadata-name projection must avoid value access at the source; stripping serialized values afterward is insufficient. The projected name must not be represented as a fully conformant accessible name when those value contributions are deliberately omitted.

[domUtils.ts](https://github.com/microsoft/playwright/blob/d1ead3ecca23182f2d06d761c28e3d4edafb6595/packages/injected/src/domUtils.ts#L28-L192): `parentElementOrShadowHost`, `closestCrossShadow`, `computeBox`, `isElementStyleVisibilityVisible`, `beginDOMCaches`. Handles composed ancestry, `display:contents`, visible text boxes, `checkVisibility`, closed details and layout caches. Distinguish layout visibility from ARIA visibility and pointer eligibility. FreightDesk currently combines client rects, visibility and hidden ancestors into one Boolean. Reuse small helpers with Apache notices and bounded root scope; do not equate visibility with read-only action safety. Browser-specific workarounds require tests and should not import unused engines.

## PW2 — compact semantic tree and local references

[ariaSnapshot.ts](https://github.com/microsoft/playwright/blob/d1ead3ecca23182f2d06d761c28e3d4edafb6595/packages/injected/src/ariaSnapshot.ts#L81-L307): `generateAriaTree`, `computeAriaRef`, `toAriaNode` build an ARIA-node tree plus `info` and `refs` maps and iframe references. Traversal visits assigned slots, open shadow children and ARIA-owned nodes while preventing duplicate visits. Reference reuse checks the same element's role/name; it does not establish identity after document replacement. Mode-specific visibility differs: AI mode admits ARIA-visible **or** layout-visible nodes. Inputs/textareas become value-bearing children, links contribute URLs and CSS generated text may enter names.

**ADAPT / SAFE_TO_ADAPT_WITH_NOTICE** for representation and relation bookkeeping. Use X1 document/frame/generation-qualified local node IDs; retain raw DOM handles only in extension memory. Do not adopt stock serialization or entire-document defaults. Closed shadow roots and inaccessible frames remain coverage gaps, never grounds for new permissions. FreightDesk has a small container snapshot and no comparable normalized semantic graph.

[ariaSnapshotDistiller.ts](https://github.com/microsoft/playwright/blob/d1ead3ecca23182f2d06d761c28e3d4edafb6595/packages/injected/src/ariaSnapshotDistiller.ts#L23-L236): `runPlugins` uses one pre/post-order visitor pipeline. Plugins merge repeated text, unwrap redundant single-child generic containers, preserve click targets and track name-source references so pruning does not destroy attribution. **ADAPT** its projection-pass design; keep the evidence graph intact and prune only a derived view. FreightDesk must also preserve seemingly generic wrappers carrying heading/form relationships. These new main-branch implementations are source evidence, not a claim of years of maturity for every recent distiller change.

## PW3 — scored selector portfolios

[selectorGenerator.ts](https://github.com/microsoft/playwright/blob/d1ead3ecca23182f2d06d761c28e3d4edafb6595/packages/injected/src/selectorGenerator.ts#L37-L278): `generateSelector`, `generateSelectorFor`, `buildNoTextCandidates` create weighted token sequences and verify them against the actual target. Lower cost wins: configured test ID 1, role/name 100, label 140, CSS ID 500, ordinal 10,000. Parent-scoped combinations disambiguate; the recursive search is limited and caches text-allowed/text-disallowed cases. IDs resembling generated GUIDs are penalized by exclusion from preferred candidates. These are hand-tuned selector costs, not calibrated probabilities of correctness.

[fallback and scoring](https://github.com/microsoft/playwright/blob/d1ead3ecca23182f2d06d761c28e3d4edafb6595/packages/injected/src/selectorGenerator.ts#L359-L488): `cssFallback`, `combineScores`, `isGuidLike` rank ancestry/class/ordinal paths, penalize token position and text length, then enforce an exact target match. FreightDesk currently retains positional relative paths with semantic metadata and proposes equality-based remaps. **ADAPT / SAFE_TO_ADAPT_WITH_NOTICE** the tested multi-strategy search, uniqueness check and cost accounting. Do not persist private names or blindly accept ordinal fallbacks. The internal `InjectedScript` parser/evaluator and role utilities are dependencies; implement typed X1 locator plans instead of importing Playwright's server/executor or arbitrary selector commands.

## PW4 — cancellation and fresh document resolution

[frames.ts](https://github.com/microsoft/playwright/blob/d1ead3ecca23182f2d06d761c28e3d4edafb6595/packages/playwright-core/src/server/frames.ts#L1155-L1251): `retryWithProgressAndTimeouts`, `isNonRetriableError`, `_retryWithProgressIfNotConnected` resolve a fresh handle, separate retryable detachment from terminal errors, race waits with page/frame closure, and dispose handles. [Context replacement](https://github.com/microsoft/playwright/blob/d1ead3ecca23182f2d06d761c28e3d4edafb6595/packages/playwright-core/src/server/frames.ts#L1785-L1817) resets context promises by world and invalidates old contexts.

**REIMPLEMENT / PREFER_CLEAN_REIMPLEMENTATION** of the lifecycle model behind existing X1, because Playwright's server/context/connection system is unnecessary here. Preserve X1's stronger lease, owner-presence and document-binding checks. Retry pure observation only within a bounded budget; never reuse a stale observation or repeat an uncertain navigation action automatically. This is a source-reference recommendation, not permission to reopen the closed Playwright live executor.

## RR1 — node identity ledger

[utils.ts](https://github.com/rrweb-io/rrweb/blob/32ed9fe5387e088cfc023c71a39672c30c516da7/packages/rrweb-snapshot/src/utils.ts#L192-L290): `Mirror` maintains ID→Node `Map` and Node→metadata `WeakMap`; supports add, replace, remove and reset. Removing a live ID does not erase the node's weak metadata, which helps distinguish moves/reinsertions. The adjacent `maskInputValue` accepts already-read values and can preserve their length: do not import it into metadata mapping.

**ADAPT / SAFE_TO_ADAPT_WITH_NOTICE** for a document-scoped mirror with explicit lifecycle and bounded retention. Strip recorder metadata and reset on a verified document epoch change. FreightDesk's current snapshot uses `Map<Element,{visible,selected}>` only for one before/after comparison; it lacks a reusable node ledger. Mirror IDs are session-local physical identity, not stable business identity or cross-document selectors. Dependencies of this small class are types; the whole source utility file has unrelated CSS/replay dependencies and should not be copied wholesale.

## RR2 — mutation coalescing and ordered diffs

[mutation.ts](https://github.com/rrweb-io/rrweb/blob/32ed9fe5387e088cfc023c71a39672c30c516da7/packages/rrweb/src/record/mutation.ts#L137-L261): `MutationBuffer` collects added/moved/dropped sets, removals and attribute cursors, avoiding duplicate descendants from batched MutationObserver records. [Emission](https://github.com/rrweb-io/rrweb/blob/32ed9fe5387e088cfc023c71a39672c30c516da7/packages/rrweb/src/record/mutation.ts#L263-L508) delays additions until parent/next-sibling IDs exist, drops removed subtrees and omits redundant text/attribute changes on freshly serialized nodes. [genAdds](https://github.com/rrweb-io/rrweb/blob/32ed9fe5387e088cfc023c71a39672c30c516da7/packages/rrweb/src/record/mutation.ts#L768-L807) recognizes moves and recursively deduplicates additions, including shadow children.

**REIMPLEMENT / PREFER_CLEAN_REIMPLEMENTATION** using MIT-attributed algorithm provenance: borrow coalescing/order invariants, but write a bounded metadata-only journal without rrweb's raw text, inputs, styles, replay or whole-page serialization. Dependencies include Mirror, serializer, managers and DOM wrappers. Mutation records alone do not detect every computed visibility change and do not prove which action caused a change. Add targeted state resampling after an authorized action, sequence fences and competing-action detection. FreightDesk's fixed-container before/after diff is narrower and safe but misses generic region changes and persistent correlation.

## RR3 — frame/shadow lifecycle, with exclusions

[snapshot.ts](https://github.com/rrweb-io/rrweb/blob/32ed9fe5387e088cfc023c71a39672c30c516da7/packages/rrweb-snapshot/src/snapshot.ts#L924-L1160): `serializeNodeWithId` tags document roots, shadow hosts/children and delayed iframe attachment, with masking/slimming hooks. [ShadowDomManager](https://github.com/rrweb-io/rrweb/blob/32ed9fe5387e088cfc023c71a39672c30c516da7/packages/rrweb/src/record/shadow-dom-manager.ts#L25-L145) deduplicates observed roots, stores disconnect callbacks and patches `attachShadow`. [IframeManager](https://github.com/rrweb-io/rrweb/blob/32ed9fe5387e088cfc023c71a39672c30c516da7/packages/rrweb/src/record/iframe-manager.ts#L15-L99) binds frame sources and remaps recorder IDs.

**REFERENCE / REFERENCE_ONLY** for root ownership and cleanup. Do not adopt prototype patching, cross-origin message federation, input/event recording or session replay. Existing X1 has `all_frames=false`, exact Ascend host scope and an isolated content world; this audit authorizes no expansion. V2 should represent inaccessible frames/closed shadow roots as explicit gaps. A future frame sensor requires a separate permission and identity design; no flat cross-frame selector assumptions.

## AX1 — table slots and header associations

[to-grid.js](https://github.com/dequelabs/axe-core/blob/4d306cbb7c456849c6f964444a6a7174d2be502a/lib/commons/table/to-grid.js#L11-L55): `toGridMemoized` constructs a two-dimensional occupancy array and expands spans rather than assuming child index equals logical column. [get-headers.js](https://github.com/dequelabs/axe-core/blob/4d306cbb7c456849c6f964444a6a7174d2be502a/lib/commons/table/get-headers.js#L15-L102): explicit `headers` IDREFs take priority, otherwise row/column searches use header predicates and cached virtual nodes. Dependencies: virtual tree, memoization, DOM IDREF resolution and header semantics.

**REIMPLEMENT / PREFER_CLEAN_REIMPLEMENTATION** from the HTML table model, using axe as a comparison oracle subject to test-use licensing. It is stronger than current fixed one-row header alignment for genuine spanned tables, but not a complete provider grid contract. The examined zero-rowspan handling extends to `rows.length`, while the [HTML model](https://html.spec.whatwg.org/multipage/tables.html#processing-model) scopes zero to the remaining row group; RTL is also explicitly TODO in header traversal. Do not copy those limitations. FreightDesk should retain clone rejection, unique data-bearing grid, required-header semantics and coverage proof.

[is-data-table.js](https://github.com/dequelabs/axe-core/blob/4d306cbb7c456849c6f964444a6a7174d2be502a/lib/commons/table/is-data-table.js#L16-L192) combines semantic structures, roles, dimensions, borders and colors. **REFERENCE** for candidate features only: a table with a header can still be Ascend's header clone; a real one-row result must not become “layout” merely from size. Neither this code nor standard slot normalization solves virtualized off-screen rows, partial ARIA grids or pagination completeness.

## AX2 — composed tree and label context

[get-flattened-tree.js](https://github.com/dequelabs/axe-core/blob/4d306cbb7c456849c6f964444a6a7174d2be502a/lib/core/utils/get-flattened-tree.js#L33-L179): virtual nodes retain ancestry/shadow scope, flatten assigned slots and create weak node/selector indexes. Some slot-box behavior is intentionally disabled in source. [label-text.js](https://github.com/dequelabs/axe-core/blob/4d306cbb7c456849c6f964444a6a7174d2be502a/lib/commons/text/label-text.js#L14-L95) merges implicit/explicit labels in DOM order and considers exposed form-associated custom-element labels. These depend on axe's virtual node/cache/text subsystem; ElementInternals is not freely available from every external sensor.

**REFERENCE / REFERENCE_ONLY**, preferring Playwright's Apache helper family for implementation and standards for a fresh bounded table model. Do not flatten away relation-bearing wrappers or assume a normal extension can inspect internals/closed roots. axe's MPL is not incompatible with every commercial product: source availability and licensing duties apply to covered files on distribution, with larger works allowed under section 3.3. The [Mozilla FAQ](https://www.mozilla.org/en-US/MPL/2.0/FAQ/) explains this file boundary. Direct inclusion needs legal/package review; do not label MPL “safe with notice only.”

## Common integration conclusions

The reusable strength is mature low-level semantics, selector search and mutation bookkeeping. None of these files supplies FreightDesk's tenant/workspace proof, read/write policy, operational semantic truth, uncertainty handling across real loads or safe causal action binding. Keep those as native responsibilities. All borrowed helpers must be rooted in the same verified X1 document, use explicit budgets, return competing candidates rather than arbitrary winners, and pass metadata-value traps before incorporation.

The source snapshots and per-file SHA-256 manifests are research evidence only. A later adaptation must retain the applicable license/copyright/NOTICE material, document modifications and audit transitive dependencies. A clean implementation must be independently written from a documented algorithm/specification; renaming copied source is not an independent implementation.
