## Skyvern: useful decomposition, substantial incompatibilities

### S1. Compact DOM representation with separate flat and nested indexes

Source: [`buildElementTree`](https://github.com/Skyvern-AI/skyvern/blob/35cfb314f4777ad77130dae087b26aa3ef99c489/skyvern/webeye/scraper/domUtils.js#L2413-L2605), [`buildElementObject`](https://github.com/Skyvern-AI/skyvern/blob/35cfb314f4777ad77130dae087b26aa3ef99c489/skyvern/webeye/scraper/domUtils.js#L2176-L2355), [`trim_element` / attribute projection](https://github.com/Skyvern-AI/skyvern/blob/35cfb314f4777ad77130dae087b26aa3ef99c489/skyvern/webeye/scraper/scraper.py#L1118-L1237).

The browser walk returns both a flat element collection and a nested tree. Node records include tag, attributes, text, frame, children, interactability, pseudo-text and select options. It prunes head/options and distinguishes structural wrappers from actionable elements; table-related tags survive to preserve hierarchy. It descends open shadow roots and can retain wrappers with a `purgeable` marker, allowing the prompt renderer to omit wrapper markup without discarding descendants. `maxElementNumber` limits emitted elements when configured; zero means no such limit. The implementation does not provide a hard bound on every visited DOM node. Parent lookup uses a linear `elements.find`, so the whole walk is not automatically linear.

Useful design: maintain a normalized node store plus derived projections, rather than making one serialized tree simultaneously serve locators, prompts, schema extraction and action execution. Preserve structural table/form/region nodes even when they are not interactive. Emit explicit coverage/truncation metadata rather than claiming omitted nodes are absent.

**Do not transplant the collector.** It stamps `unique_id` attributes into the provider DOM, reads ordinary input/textarea values, copies arbitrary attributes/text, and masks password length rather than removing all value information. These behaviors violate the current metadata-only X1 sensor contract. Use isolated-world `WeakMap<Element, NodeId>` identities and a whitelist projection that never reads values. Scope traversal to the verified workspace and separately budget visited nodes, emitted nodes, attributes, depth, serialized bytes and elapsed time.

Compared with FreightDesk, this is richer representation engineering. Current [`webbridge.js`](../../extensions/ascend-x1/webbridge.js) indexes a few semantic container types and [`workspace.js`](../../extensions/ascend-x1/workspace.js) emits field proposals directly. Neither is yet a general immutable `DocumentGraph`. **REIMPLEMENT the decomposition; REFERENCE_ONLY for Skyvern code.**

### S2. Distinguish ephemeral IDs, position-sensitive hashes and structural identity

Source: [`clean_element_before_hashing`, `hash_element`, `structural_identity`, `build_element_dict`](https://github.com/Skyvern-AI/skyvern/blob/35cfb314f4777ad77130dae087b26aa3ef99c489/skyvern/webeye/scraper/scraper.py#L178-L281); [cached-action matching](https://github.com/Skyvern-AI/skyvern/blob/35cfb314f4777ad77130dae087b26aa3ef99c489/skyvern/webeye/actions/caching.py#L72-L145).

`hash_element` recursively removes injected ID, rectangle and frame index, then hashes sorted JSON. `structural_identity` additionally removes XPath and frame location, preserving tag/attributes/text/descendant shape. It intentionally retains volatile provider IDs: stripping all distinguishing identity would create false equivalence. The dictionary builder produces ID→element, ID→frame, ID→hash and hash→IDs indexes. Cached-action matching advances only for one hash match and stops a plan prefix on zero or multiple matches.

This is a useful model for V2: `DocumentInstanceId`, `NodeRef`, `ShapeFingerprint`, `SemanticFingerprint` and `Locator` are different concepts. The semantic hash must not be represented as proof that two workspaces have the same load identity. A hash match is useful only inside a fresh exact workspace/session boundary and still needs collision/duplicate handling.

FreightDesk currently hashes sanitized candidate metadata and compares exact semantic tuples in `AdaptiveLocator`; it lacks a general position-independent relocation index. **REIMPLEMENT** separate fingerprints and a multimap that explicitly represents duplicate matches. Do not include raw text/values in durable mapping hashes just because Skyvern does. **IGNORE** cached operational-action execution; X1 ActionPolicy remains authoritative.

### S3. Frame topology and bounded stale-frame re-resolution

Source: [frame enumeration/filtering/stitching](https://github.com/Skyvern-AI/skyvern/blob/35cfb314f4777ad77130dae087b26aa3ef99c489/skyvern/webeye/scraper/scraper.py#L749-L877); [`resolve_locator`](https://github.com/Skyvern-AI/skyvern/blob/35cfb314f4777ad77130dae087b26aa3ef99c489/skyvern/webeye/utils/dom.py#L159-L214).

A frame record refers to its parent frame's element. Frame subtrees are stitched into **both** the flat and nested representations: serialization may preserve object aliasing in one engine and duplicate objects in another. Locator resolution reconstructs the frame ancestry and walks through content frames. A detached frame-element handle is re-queried once; repeated detachment becomes a missing-element error. Excluded frames may receive non-interactable placeholder records, so inaccessible content is visible as a coverage gap without becoming a target.

FreightDesk's current X1 routes are top-frame bound. V2 should represent frame/shadow boundaries now, but additional sensor permissions or frame execution require separate authorization. Importing Skyvern's Playwright frame API or cross-origin traversal is inappropriate. **REIMPLEMENT** frame-aware references, coverage placeholders, and a single bounded re-resolution principle inside existing X1 authority. A new document still requires fresh proof; no stale receipt transfer.

### S4. Control→target relationships need IDREF state plus rendered geometry

Source: [`resolveAriaPopupTargets` and rendered-area checks](https://github.com/Skyvern-AI/skyvern/blob/35cfb314f4777ad77130dae087b26aa3ef99c489/skyvern/webeye/scraper/domUtils.js#L825-L961); [interactability classifier](https://github.com/Skyvern-AI/skyvern/blob/35cfb314f4777ad77130dae087b26aa3ef99c489/skyvern/webeye/scraper/domUtils.js#L1251-L1474).

The popup resolver splits `aria-controls`/`aria-owns` IDREF lists and distinguishes **no relationship declared**, **dangling relationship**, and **resolved target**. A visible trigger with a stale expanded flag is insufficient: targets must visibly paint area, considering zero-sized containers, clipping and visible descendants escaping overflow. The classifier combines native tags, roles, disabled state, pointer behavior and several framework-specific widget patterns.

Useful general concepts: keep a typed `ControlTargetEdge` with relationship source, resolution cardinality and present/visible/rendered facts; distinguish structural visibility from viewport/actionability. Existing FreightDesk supports controls/labelledby/fragments/data targets but mostly tests client rectangles and hidden flags. Multiple IDREF targets should be represented, not collapsed into a guessed single panel.

Limitations: this Skyvern popup helper searches light DOM, returns the first open trigger, treats no-IDREF expanded triggers as an open-popup fallback, and its descendant rendered-area walk has no explicit count/depth cap. It is not deterministic section identity for a freight workspace. General-purpose widget hacks are not a provider contract. **REIMPLEMENT** target-state distinctions and bounded geometry checks; **IGNORE** the no-IDREF fallback as proof and the framework-specific classifier as an authority rule.

### S5. Field/label association is instructive but weaker than an evidence graph

Source: [`getLabel`, `isStableId`, `buildSelector`](https://github.com/Skyvern-AI/skyvern/blob/35cfb314f4777ad77130dae087b26aa3ef99c489/skyvern/core/script_generations/extract_form_fields.js#L17-L140); [field and option records](https://github.com/Skyvern-AI/skyvern/blob/35cfb314f4777ad77130dae087b26aa3ef99c489/skyvern/core/script_generations/extract_form_fields.js#L433-L470).

The label chain uses explicit `label[for]`, wrapping label, fieldset/legend context, ARIA label, labelledby, placeholder, custom checkbox siblings, up to four ancestor/preceding-sibling text candidates, then title. Fieldset context improves ambiguous labels such as Month/Day/Year. Selector choice favors name, automation ID, label text, screened IDs, then fallbacks. Output includes required/type/format hints and select option labels/values.

Do not copy the ordering as truth. The first candidate wins; `aria-labelledby` is looked up as a single ID rather than an IDREF list; preceding-sibling prose may be unrelated; generated `:visible`/`:has-text` selectors require Playwright extensions and are not native CSS. Name and automation attributes are assumed stable without longitudinal proof or uniqueness checks. Unknown labels must remain candidates rather than becoming canonical field meanings. Options may contain private operational data.

FreightDesk already collects multiple explicit label/ARIA signals and rejects conflicts, but lacks fieldset/group context and many generic control types. **REIMPLEMENT** group/legend context as another evidence edge; keep multiple label candidates, exact IDREF token handling and conflict rejection. **REFERENCE** the rest as fixture inspiration. Initial V2 mapping records contain structural presence only, with no field-value access. A future value-presence boolean would still require a separately authorized value-reading contract; it is not a privacy bypass. Do not collect option values or free-form hints.

### S6. Incremental changes and animation-aware observation are separate from causality

Source: [incremental observer](https://github.com/Skyvern-AI/skyvern/blob/35cfb314f4777ad77130dae087b26aa3ef99c489/skyvern/webeye/scraper/domUtils.js#L3403-L3555); [`TransientPageTextObserver.start`](https://github.com/Skyvern-AI/skyvern/blob/35cfb314f4777ad77130dae087b26aa3ef99c489/skyvern/webeye/transient_page_observer.py#L105-L309); [limits](https://github.com/Skyvern-AI/skyvern/blob/35cfb314f4777ad77130dae087b26aa3ef99c489/skyvern/webeye/transient_page_observer.py#L19-L28).

The incremental collector handles added element nodes, hidden→shown changes, selected class patterns and dropdown-specific changes, then reparses changed subtrees. Its own injected-ID mutations are excluded. It observes the whole body plus a selected shadow root, uses global mutable queues/maps and has an explicit TODO for recreated-node duplicates. It is not a causal graph and does not reliably prove that an action caused a changed container.

The transient observer has a useful independent idea: a bounded set of up to 50 newly admitted invisible nodes gets per-node 900ms deadlines and a shared 100ms visibility sweep, catching animation-to-visible changes that produce no second DOM mutation. It bounds stored text events to 100 but captures up to 500 characters per event and observes broadly. **REIMPLEMENT** only the per-node deferred-visibility scheduling and observer-install lifecycle pattern, on sanitized scoped node records. **IGNORE** text persistence and page-wide collection.

FreightDesk's A/B/C/D causal ranking (direct target/new/newly visible/connected selection) is more appropriate for its exact-action contract. Keep that evidence, but replace DOM-reference-only diffing with node matching that handles remounts and clearly separates external/background changes. No inspected Skyvern routine solves control→region causality independently of time correlation.

### S7. Agentic verification is a fallback input, not operational evidence

Source: [`complete_verify` state/history prompt and result handling](https://github.com/Skyvern-AI/skyvern/blob/35cfb314f4777ad77130dae087b26aa3ef99c489/skyvern/forge/agent.py#L5180-L5319).

The verifier combines refreshed element representation, goal/termination criteria, optional action history and screenshots, calls an LLM, validates the returned schema, and converts it into complete/terminate/continue. Retaining action history is valuable because a final page alone cannot prove an action sequence occurred. A schema-valid LLM response does not establish provider identity or authorize navigation/writes. **REFERENCE** history-aware verification design; **IGNORE** the agent runtime and direct operational loop. A FreightDesk semantic fallback may propose graph relations or request a bounded observation; deterministic X1 checks must accept or reject them.

## Healenium: transparent adaptive candidates, unsuitable automatic authority

### H1. Actual algorithm and scoring

Source entry: [`HealingService.findNewLocations`](https://github.com/healenium/healenium-web/blob/c1e4f83d8995c2928ea1e09e721a7ac9f421bd69/src/main/java/com/epam/healenium/service/HealingService.java#L55-L79). Algorithm implementation is in the version/hash-pinned Maven sources noted above; inspect local [PathFinder.java](<C:/FreightDeskRuntime/Data/Research/WebBridgeV2/healenium-tree-comparing/sources/com/epam/healenium/treecomparing/PathFinder.java:65>), [LCSPathDistance.java](<C:/FreightDeskRuntime/Data/Research/WebBridgeV2/healenium-tree-comparing/sources/com/epam/healenium/treecomparing/LCSPathDistance.java:14>), [HeuristicNodeDistance.java](<C:/FreightDeskRuntime/Data/Research/WebBridgeV2/healenium-tree-comparing/sources/com/epam/healenium/treecomparing/HeuristicNodeDistance.java:11>) and [Node.java equality](<C:/FreightDeskRuntime/Data/Research/WebBridgeV2/healenium-tree-comparing/sources/com/epam/healenium/treecomparing/Node.java:69>). These are source-archive links, not unverifiable GitHub permalinks.

Input is a historical root→target `Path<Node>` and a new parsed DOM `Node` tree. Nodes contain tag, ID, classes, sibling index, other attributes, aggregate inner text, children and parent. `Node.equals` compares only tag and ID. `PathFinder` materializes every root→leaf path, computes dynamic-programming LCS against the historical path, and scores nodes in the suffix beginning at the LCS index. Candidates are grouped by score, sorted descending, filtered by cap, then limited. The Web adapter asks for up to 1000 scored nodes, attempts locator construction and retains at most `recovery-tries` healed elements.

`HeuristicNodeDistance` uses these weights: tag 100, normalized LCS 100, ID 50, classes 40, text/value 30, other attributes 30, sibling index **0**; denominator 350. The LCS normalization divisor passed by `PathFinder` is `min(best observed LCS, historical path length)`, rather than always the complete historical depth. ID/text use bounded Levenshtein with approximately 30% edit tolerance; other attributes and class comparisons use approximately 75%. Boolean text requires exact equality. Classes combine set overlap and fuzzy differences. Empty class/other-attribute sets earn their full corresponding weight. A zero normalization divisor, or a divisor over five with LCS fraction below 0.7, yields score zero. Current Web defaults are [`score-cap=.6`, `recovery-tries=1`](https://github.com/healenium/healenium-web/blob/c1e4f83d8995c2928ea1e09e721a7ac9f421bd69/src/main/resources/application.conf#L1-L8).

This is a deterministic heuristic, not evidence of a trained model or calibrated probability. No inspected scorer enforces immutable business identity, action type or exact field meaning. Similar generic inputs can score highly on common ancestors/tag plus missing attributes. A high score must never heal a Save control into a read-only tab or transfer a field across loads.

Complexity/limits: LCS allocates an `(m+1)*(n+1)` matrix per compared leaf path; whole-tree path materialization and repeated candidate nodes can be costly. There is no workspace-scoped candidate budget in this algorithm. Static Jsoup parsing lacks computed visibility, geometry, shadow content and browser accessibility state. A single selected candidate is not proof of a correct match; ties need an explicit margin/ambiguity rule.

**V2 recommendation: REIMPLEMENT** a metadata-only candidate retriever inspired by this separation: ancestor-path similarity plus field/control feature similarity, with hard identity/type/navigation gates before scoring. Retrieve within one verified region, deduplicate by NodeRef, normalize using available evidence without rewarding missing information, require explicit competing-candidate margins, and persist feature contributions. Weight selection needs adversarial fixtures and later labeled observations; do not copy `.6` as an acceptance threshold.

### H2. Selector escalation and history are useful; backend capture is not

Source: [ordered selector components and unique-match validation](https://github.com/healenium/healenium-web/blob/c1e4f83d8995c2928ea1e09e721a7ac9f421bd69/src/main/java/com/epam/healenium/service/HealingService.java#L39-L116); [historical path collector](https://github.com/healenium/healenium-web/blob/c1e4f83d8995c2928ea1e09e721a7ac9f421bd69/src/main/resources/itemsWithAttributes.js#L1-L31); [save/page-source/screenshot behavior](https://github.com/healenium/healenium-web/blob/c1e4f83d8995c2928ea1e09e721a7ac9f421bd69/src/main/java/com/epam/healenium/SelfHealingEngine.java#L95-L162).

Selector detail grows from tag+ID, tag+class, parent combinations, position, attributes, then full path. Candidate locators must return exactly one element and must not duplicate an already used remote element. Failed locators are excluded. Optional XPath generation is delegated to a service. This is an actionable pattern for a `LocatorCandidate[]` portfolio, but the accepted locator is returned to test execution automatically; FreightDesk must instead propose and reverify within its action policy.

The collector walks to `document`, copies all non-ID/class attributes and `innerText`, and returns full `window.location.href`. The engine stores historical paths through a backend, obtains page source and can draw a red border before taking a screenshot. Those are outside metadata-only mapping. It depends on Selenium/RemoteWebDriver, Typesafe Config, Java tree-comparing/Jsoup/Commons and backend/selector services. Do not import that transport, storage, screenshot or action interception stack.

FreightDesk currently has strict semantic-equality remapping only; Healenium demonstrates a richer candidate layer. **ADAPT** history records, negative-locator evidence and uniqueness checks, with Apache notices if code is adapted. **IGNORE** raw snapshot storage, browser mutation for diagnostics, automatic healed-element execution and full-page matching. The actual core algorithms are simple enough to implement independently against `DocumentGraph` without Java or Selenium dependencies.

## Finder: the most practical small harvest, after bounding it correctly

### F1. Penalty-ranked CSS search and optimization

Source: [`finder` and configuration](https://github.com/antonmedv/finder/blob/a8d83110d3d035e029c571b94965b629a10a469f/finder.ts#L39-L120), [`search` and `tie`](https://github.com/antonmedv/finder/blob/a8d83110d3d035e029c571b94965b629a10a469f/finder.ts#L122-L228), [selector composition](https://github.com/antonmedv/finder/blob/a8d83110d3d035e029c571b94965b629a10a469f/finder.ts#L231-L278), [uniqueness and optimization](https://github.com/antonmedv/finder/blob/a8d83110d3d035e029c571b94965b629a10a469f/finder.ts#L348-L384).

Input is a concrete `Element`, root and filter callbacks. The `Knot` data structure stores selector text, penalty and ancestor level. Per level, it offers ID (penalty0), class (1), attribute (2), tag (5), nth-of-type (10), and nth-child (50). It enumerates combinations while walking ancestors, sorts by total penalty, and tests uniqueness. Adjacent retained levels use child combinators; omitted levels use descendant combinators. After a unique path is found, optimization recursively removes intermediate nodes, requiring both uniqueness and exact returned-element equality.

It is an understandable preference model, not a stability probability or a proof that the globally shortest selector was found. Default filters admit word-like IDs/classes and selected attributes, using a Latin-letter/vowel heuristic to reject generated-looking tokens. Default accepted attributes include role/name/aria-label/rel/href and some data attributes. Useful provider identifiers with digits or non-Latin scripts may be rejected; mutable state classes may still be accepted. Filter callbacks are therefore part of the provider policy, not harmless convenience.

No runtime npm dependency is declared in [package.json](https://github.com/antonmedv/finder/blob/a8d83110d3d035e029c571b94965b629a10a469f/package.json#L1-L35). It uses browser DOM/CSS.escape. Development libraries (jsdom, CSS.escape polyfill, TypeScript, Vitest) are not required to run an adapted browser helper and were not installed.

### F2. Hard bounds and scope must be added before adoption

The key issue is [`paths.push(...combinations(stack))`](https://github.com/antonmedv/finder/blob/a8d83110d3d035e029c571b94965b629a10a469f/finder.ts#L122-L155): combinations are eagerly materialized before returning to the outer timeout check. Many attribute/class choices across ancestors can exhaust time, memory or argument limits before `timeoutMs` is checked. The default path-check cap is Infinity; optimization checks elapsed time but is not governed by the path-check counter. The [fallback](https://github.com/antonmedv/finder/blob/a8d83110d3d035e029c571b94965b629a10a469f/finder.ts#L280-L303) emits a positional nth-of-type path when the search budget expires, which silently changes locator quality.

[Root resolution](https://github.com/antonmedv/finder/blob/a8d83110d3d035e029c571b94965b629a10a469f/finder.ts#L330-L358) selects a shadow root for an input already inside one and treats default body as document scope. This does not grant access to a closed shadow root or prove authorized workspace scope. A custom root is not explicitly validated to contain the input; initial uniqueness checks count matches without verifying target equality. V2 must independently require both containment and `querySelector(candidate) === observedElement` for every accepted candidate. A custom root must not be silently widened by shadow-root handling.

**ADAPT / SAFE_TO_ADAPT_WITH_NOTICE**, but change these behaviors before use:

1. Enforce the authorized document/frame/shadow/workspace boundary first; reject detached or out-of-root input.
2. Use bounded lazy or best-first candidate expansion with checks before expansion, not after a Cartesian product is allocated. Cap depth, choices per level, generated candidates, selector bytes, uniqueness queries, optimization checks and elapsed time.
3. Use provider-approved stable attribute filters; never place operational values, phones, notes or signed URLs into persisted selectors. Preserve a feature/penalty explanation.
4. Return several unique alternatives with quality flags and provenance. Budget exhaustion returns an explicit partial/unknown result. Positional alternatives may be retained as low-quality candidates but never silently activated.
5. Prefer semantic exact locators when they are already verified; Finder only provides CSS, not accessibility role/name computation or provider identity. Recheck exact identity, section and action classification after resolution.

FreightDesk currently persists relative child-index paths and semantic tuples; Finder supplies a mature compact candidate generator it would be wasteful to rebuild wholesale. Its safety wrapper and bounded search correction are FreightDesk work. Good tests include reordered siblings, random versus stable IDs, duplicate semantic controls, malicious/private attribute values, high-branching trees, wrong roots, shadow boundaries and a timeout before expansion. No third-party test HTML should be copied as production material.

## Cross-project design consequences

| Existing component | Proposed treatment from this research | Reason |
|---|---|---|
| BrowserSensor | KEEP X1 boundary; REFACTOR projection | No external agent/driver replaces authenticated local authority. Sensor outputs bounded metadata plus coverage. |
| DOMSnapshot | REPLACE internal representation with DocumentGraph snapshot + indexes | Separate ephemeral node references, topology, semantic fingerprints and serialized views. Preserve document/frame/shadow identity. |
| DOMDiff | REFACTOR into StateDiff + causal candidate attribution | DOM-reference comparison misses remounts; an observer event is not proof of action causality. |
| LocatorGraph | MERGE discovery into ControlGraph/SchemaGraph, keep typed evidence edges | Label, heading, target, ancestor and visibility relations should not be flattened prematurely into one field label. |
| AdaptiveLocator | REPLACE strict tuple-only matcher with bounded candidate retrieval; keep strict acceptance gates | Finder and Healenium supply candidate primitives, not permission or business identity. |
| ProviderContract | KEEP and strengthen version/provenance bindings | Generic inference remains candidate evidence until verified for the provider/workspace. |
| EvidenceScorer | REFACTOR into feature contributions + hard gates + ambiguity/margin rules | Numeric similarity, source reliability and authorization are independent. Never treat heuristic score as probability. |

Highest-priority harvests from this subset: (1) bounded Finder selector portfolio, (2) typed document/position/semantic identity separation, (3) feature-explained path+node relocation candidates, (4) explicit IDREF resolution/visibility relationships, (5) fieldset/legend label context, (6) animation-aware bounded visibility admission. Geometry-based overlap groups, agent goal verification and broad incremental collectors are secondary references, not foundations for exact section identity.

The unsolved FreightDesk-specific problem remains accepting **the same business workspace, section and logical control under an authorized action**, particularly when a remount or unrelated background update coincides with navigation. None of these projects proves that from a high similarity score. V2 must combine exact provider identity, causal edges, competing-candidate evidence, document generations, action classification and bounded postconditions. That acceptance layer and its audit are valuable FreightDesk-specific engineering; generic DOM projection, selector enumeration and similarity primitives are not.

## Provenance to record before any incorporation

For each future copied/adapted unit, record source project/repository, exact commit or versioned artifact+SHA-256, file+line range, license expression, copyright holder, notice obligations, original/adapted code paths, modification date, algorithm changes, excluded source data, tests and reviewer. Record **idea-only / independently implemented** separately from **copied / adapted**; translating code is not automatically independent reimplementation. Keep original license/NOTICE files with any permissive code that is actually incorporated. This research itself incorporates no third-party implementation.

For `tree-comparing`, the source artifact and POM are the available provenance; missing Git revision and missing archive license/header should remain explicit fields rather than guessed. For Skyvern, legal review or a suitable separate license is a blocker to direct code harvest. For Finder, conservative bounds and privacy/scope checks are engineering blockers to unmodified use.
